# Statewright Plugin 0.3.1

Statewright 0.3.1 is a reliability release for the Codex and Claude Code
plugins. Pi and OpenCode remain on the 0.2.x line, and Oh My Codex remains on
the 0.1.x line.

## What changed

- Managed Codex and Claude clients recover cleanly when a saved Statewright API
  key is rejected instead of leaving the user behind an opaque transport error.
- Claude update checks announce only a strictly newer release and merge the
  notice into the single hook response instead of corrupting hook JSON.
- Claude Stop hooks continue an active workflow with bounded nudges.
- Codex managed sessions keep root-thread route ownership isolated from nested
  reviewers and other child processes.
- Codex resume history inspection now distinguishes canonical legacy history
  from paginated history, rejects malformed or ambiguous records, and repairs
  only the narrowly recognized duplicate-settings anomaly.
- Codex writer locks and managed child teardown now have explicit lifecycles,
  preventing stale Statewright-owned writers from blocking a later resume. If
  a detached turn is still finishing, the resume error now says to wait a
  minute or two and retry instead of exposing only the raw writer conflict.
- Privacy-safe error reporting is shared across the supported plugin runtimes,
  disabled by default, and enabled only when an operator explicitly sets
  `STATEWRIGHT_SENTRY_ENABLED=true`. Credential and prompt-bearing fields are
  removed before transport; `STATEWRIGHT_SENTRY_DISABLED=true` remains an
  emergency kill switch.
- Windows bootstrap and managed-route canaries cover native `codex.cmd` and
  `claude.cmd` launchers and preserve quoted route arguments.

## Validation contract

The release gate includes source and generated-runtime parity checks, Codex and
Claude plugin contract suites, executor transport and history tests, shell
syntax, package/archive smokes, the Rust workspace suite, local Codex reinstall,
and a fresh Claude Code dogfood run against the candidate plugin. Before either
plugin tag is created, the exact main commit must also pass the hosted Windows
bootstrap suite and the authenticated macOS/Linux production-gateway matrix.
Those canaries initialize each supported plugin transport and perform only the
non-mutating `statewright_get_status` call with an isolated CI credential.

## Known host boundary

This release fixes Statewright-owned writer lifecycle and resume validation. It
does not change Codex's native global resume picker or add project-directory
labels to that host-owned interface.

## Rollback

The immediate rollback leaves tool enforcement installed but disables the
managed process-restart boundary. From the Statewright checkout used for setup,
run both commands and then restart the host CLI:

```bash
node plugins/executor/statewright-managed-client.mjs --disable --host codex
node plugins/executor/statewright-managed-client.mjs --disable --host claude
```

To remove Statewright's managed shims and marked shell-path block completely,
run `node plugins/executor/statewright-managed-client.mjs --uninstall` and open
a new shell. These operations do not alter Codex history. History repair remains
fail-closed; private backups include a target-scoped restoration procedure when
a repair was actually applied.
